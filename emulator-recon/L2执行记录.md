# L2 执行记录：99账号中心「环境违法」检测定位与绕过尝试

目标：LDPlayer14 index 1（adb `emulator-5556`，Android 14 / SDK34 / x86_64，Houdini 转译 ARM64）
对象：99账号中心 `com.nd.aqcenter`（v1.6.23 / version_code 278，NIS 壳，登录组件）；关联游戏 `com.nd.myht`
时间：2026-11-03（L2 执行区间约 16:20–16:55）

---

## 0. 结论先行

1. 「初始化失败 / 当前网络不佳」是 **WCDB 本地库 `99aqcenter.db` 打不开**（`file is encrypted or is not a database`）导致，`pm clear com.nd.aqcenter` 清数据后即消失，app 正常进入「隐私协议 → 登录页」。
2. 登录页 `com.nd.aqcenter/.login.LoginActivity` 显示后，app 在 **1–7 秒内必现 SIGSEGV**，崩在 `libaqcenter.so` 的 C++ 异常展开路径（`_Unwind_Resume`，空异常对象指针），宿主侧 4 帧全部落在 `libhoudini.so` —— 即 **Houdini 转译 x86_64 上 C++ 异常展开 bug/反仿真触发**，不是普通空指针。
3. 该崩溃 **与 root 无关**（root 开/关都崩）、**与 `ro.product.cpu.abi*` 无关**（改成 arm64-v8a 也崩）、**与数据新旧无关**（清数据后同样崩）。
4. `libaqcenter.so` 内静态可提取大量环境检测点（qemu/vbox/nox/mumu/雷电 痕迹、/proc 特征、x86_64、/system/xbin/su、magisk、ptrace、指纹等），但 **「环境违法」四个字不在任何本地 dex/资源/so 中** → 该文案极可能是**服务端下发**，或藏在 NIS 运行时解密后的真实 dex 里。本机未能复现「环境违法」弹窗（等价阶段直接崩溃，见 §3/§4）。
5. **L2 卡点**：仅靠客户机用户态环境清理无法让 99账号中心通过登录阶段。要么换 ARM64 真机/模拟器（无 Houdini），要么对 `libaqcenter.so` 做运行时补丁（NIS 完整性风险，属 L4 动态对抗范畴），要么宿主/内核层做 /proc 与特征屏蔽。

### 1.5 崩溃根因（ARM 侧 + 宿主侧对照）

ARM 侧（Houdini 打印，`runs/l2/logcat_abi.txt`）：

```
arm backtrace: pc = 0000400021c94660, lr = 0000400021c9465c
  #00  pc 0000000000e9465c  /data/data/com.nd.aqcenter/files/templib/libaqcenter.so
  #01  pc 0000000000e94658  /data/data/com.nd.aqcenter/files/templib/libaqcenter.so
  r00(r19)=0x0000000000000000
```

反汇编确认（`disasm_arm64.py` / radare2）：

```
0x00e94650  mov x19, x0
0x00e94654  ldp x29, x30, [sp], #0x10
0x00e94658  bl 0xe9818c            ; 实际进入 _Unwind_Resume 辅助
0x00e9465c  ldr x3, [x19, #0x10]   ; x19=0 → 读 0x10 → SEGV_MAPERR
```

宿主侧（`runs/l2/dropbox_full.txt`，16:53:37 `data_app_native_crash`，PID 2302）：

```
signal 11 (SIGSEGV), code 1 (SEGV_MAPERR), fault addr 0x0000000000000010
Cause: null pointer dereference
4 total frames
backtrace:
  #00 pc 00000000001053af  /system/vendor/lib64/libhoudini.so
  #01 pc 00000000001caa3b  /system/vendor/lib64/libhoudini.so
  #02 pc 00000000000e6bdf  /system/vendor/lib64/libhoudini.so
  #03 pc 000000000030e5e0  /system/vendor/lib64/libhoudini.so
```

解读：`libaqcenter.so`（ARM64）在登录阶段抛 C++ 异常 → Houdini 转译执行 `_Unwind_Resume(NULL)`（空异常对象）→ 宿主侧 null deref。真机 ARM64 上该异常会被外层捕获并走「环境违法」提示分支；LDPlayer x86_64 的 Houdini 在这里直接崩进程。

## 3. 清理实验与结果（每步真实回显）

| # | 清理项 | 操作 | 结果 |
|---|---|---|---|
| 1 | 本地 WCDB 库 | `pm clear com.nd.aqcenter`（先备份，见 §5） | 「初始化失败」消失，可到登录页 |

## 4. 卡点（为什么 L2 到此为止）

- 崩溃本质是 **Houdini 在 x86_64 上执行 libaqcenter.so 的 C++ 异常展开时把异常对象置空**，`_Unwind_Resume(NULL)` 读 0x10 崩掉。这层不是「改几个属性」能绕过的：属性、root、数据都已被排除（§3）。
- 异常是登录阶段触发的原生环境检查抛出的；静态字符串表明检查覆盖 qemu/vbox/nox/mumu//proc/x86_64/root 等模拟器特征。其中 qemu 设备节点、/proc 内容、x86_64 转译本身都无法从客户机用户态抹除。
- 因此「环境违法」在 LDPlayer x86_64 + Houdini 上**无法仅靠 L2 环境清理放行**。可放行的路径（供后续选型）：
  1. ARM64 真机 / ARM 云真机：无 Houdini 转译，异常会被捕获并走到「环境违法」提示分支（需在真机验证）。
  2. 对 `libaqcenter.so` 运行时补丁（宿主侧 gg 零痕迹写内存，把 `AntiDebug::anti/anti_inner` 起线程处或检查返回值改掉）——属 L4 动态对抗，NIS 完整性校验风险需先评估。
  3. LDPlayer 宿主侧 / 内核层 /proc 与设备节点屏蔽（`check_qemu_drivers_`、qemu_pipe 等），超出本机用户态能力。

> 真实结果：未复现「环境违法」弹窗。在等价触发阶段（登录页）进程直接崩溃，因此弹窗文案无从出现在本机。
