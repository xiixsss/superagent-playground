## 7. 结论：表层伪装 vs 真实裸露 + 修复顺序

### 7.1 雷电已经做的表层伪装（不要重复做）
- 机型三件套：`brand=REDMI, model=25102RKBEC, manufacturer=REDMI`
- `ro.hardware=qcom`、`ro.hardware.egl/vulkan=adreno`
- Android 14 / sdk 34 / 指纹格式（表面看起来是 Xiaomi 14）
- 包层干净：无 Magisk/SuperSU/Xposed/Frida 包
- hosts 干净、serial 非默认 emulator 串

### 7.2 仍然真实裸露的（按性价比排序）
1. **`ro.boot.qemu=1`** —— 最便宜也最致命的暴露。
2. **`unicorn` 设备名 + 五个分区 fingerprint + `ro.board.platform=aosp-user`** —— 深指纹全裸。
3. **`/system/build.prop` 明文含 `u-emulator` / `ld_generic_x86_64` / `device/leidian/`** —— grep 即中。
4. **`phone.*` 全家桶（dnplayer/version/openid/index/multi_count/pc_mac）** —— LD 私有属性全裸。
5. **VirtualBox 痕迹（vboxguest.ko / vboxsf.ko / /dev/vboxguest / 52:54 网关 OUI）** —— hypervisor 本质。
6. **cmdline（nosmap/nosmep/mitigations=off/selinux=permissive）+ ro.debuggable=1 + su 守护进程**。
7. **硬件类（传感器全 5Hz、伪基站哨兵值、虚拟摄像头、假 adreno EGL 壳）**。
8. **x86_64 + libhoudini + 服务器 CPU hypervisor flag** —— 跑 ARM 游戏的结构性代价。

### 7.3 建议修复顺序
- **第一批（L1，立即可做，成本低收益大）**：`ldconsole modify` 换全套标识（IMEI/IMSI/SIM serial/Android ID/MAC/model/manufacturer/pnumber）+ 按需 `--root 0`；`resetprop` 抹 `ro.boot.qemu`、`ro.product.device`、`ro.board.platform`、`ro.debuggable`、`ro.build.characteristics`。命令原文见 `L1属性伪装方案.md`。
- **第二批（L2，镜像级）**：统一 system/vendor/odm/bootimage 分区指纹；删 build.prop 构建路径；cmdline 去 permissive/nosmap/nosmep；ro.treble=true；bootloader/baseband 给值；隐藏/改名 ld* 二进制；phone.* 属性生成逻辑。
- **第三批（L3，不可行/接受）**：VirtualBox 客户机设备、x86_64 + libhoudini、服务器 CPU 与 hypervisor flag、52:54 网关 OUI。这些是雷电运行机制本身，只能接受残余风险或用真机方案替代。
